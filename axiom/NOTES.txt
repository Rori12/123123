ЗАДАЧА
------
Скриптовая кисть для мода Axiom (Script Brush, Lua): найти блоки-цели
(листва), в воздух рядом ставить другие блоки (кнопки разных видов дерева),
повёрнутые к цели, в случайном порядке, с выбором блоков в окне кисти.
Пример, не ограничение: цели и ставимые блоки меняются (рычаги на камне,
аметист, лестницы).

ФАЙЛЫ (папка axiom/)
--------------------
attach_brush.lua            рабочая кисть
test_0_diagnostic.lua       воздух -> зелёное стекло, дубовая листва -> красная
                            шерсть, синяя шерсть над ней
test_1_place_anything.lua   return blocks.red_wool (самый простой тест)

test_3_stages.lua           пошаговый тест, цвет шерсти показывает, где скрипт упал
Скрипты кистей пользователь просит отдавать ФАЙЛОМ (SendUserFile), удобным
для копирования: открыть, Ctrl+A, Ctrl+C, вставить в Tool Options.

ЧТО НЕ РАБОТАЛО И ПОЧЕМУ
------------------------
ГЛАВНАЯ ПРИЧИНА. Блок, выбранный в окне настроек ($blockState(...)$), НЕ равен
значению getBlock(x,y,z) для той же листвы. Выбранный блок приходит с другими
свойствами (вероятно persistent=true, как у блока из инвентаря), а getBlock
даёт состояние без свойств. Сравнение `getBlock(x,y,z) == target` всегда
давало false: скрипт молча ничего не находил, ошибок не было.
  Доказательство: test_3 с `== t1` (значение из окна) не изменил листву;
  тот же тест с `== blocks.oak_leaves` сработал.
  РЕШЕНИЕ: цели сравнивать с blocks.<имя> (isLeaves() в скрипте). Значение из
  окна ($blockState) использовать только как ставимый блок, не для сравнения.
  Окно "Custom target" может не сработать по той же причине; для любых блоков
  надёжнее галочка "Any solid block is a target" (isSolid).

ДОПОЛНИТЕЛЬНЫЕ ПРОБЛЕМЫ (исправлены)
- Первая версия брала все настройки из Lua-таблиц, окна выбора блоков не было.
- Скобки в названии настройки, например $boolean(Face the target (not away),false)$,
  ломают разбор $...$ (разбор идёт по скобкам). Названия: без скобок, без
  лишних символов.
- Скрипт полагался на то, что кисть обходит воздух, и ставил блок через return
  в воздухе. Теперь он срабатывает на самой цели и ставит соседей через
  setBlock. Тест 0 показал, что кисть обходит и воздух, и листву.
- В скрипте были pcall, ipairs, getBlockProperty, string, local function,
  blocks[имя_строкой]. Их нет в официальной документации Axiom; всё убрано,
  оставлены getBlock, setBlock, withBlockProperty, isSolid, blocks.<имя>,
  math.floor/math.sin, обычные for/if/function. Работоспособность math.sin и
  withBlockProperty подтверждена тестом по шагам.
- Блоки без направления вверх/вниз (лестница): настройка "Facing may be up or down".

ПРОВЕРЕННЫЕ ФАКТЫ ОБ AXIOM
--------------------------
- Кисть вызывает скрипт для каждого блока в сфере, включая воздух.
- return blocks.X меняет блок в точке x,y,z; setBlock(x,y,z,id) ставит блок,
  в том числе со смещением (x,y+1,z); перекрывает предыдущий return/setBlock.
- Ошибок в Lua Axiom в интерфейсе не показывает: при падении скрипт просто
  ничего не делает. Диагностируйте по цвету блоков (test_3_stages.lua).
- Красное и зелёное в просмотре изменений (diff) в чате означает удалённые и
  добавленные строки, а не ошибки.
- Документация: github.com/Moulberry/AxiomDocumentation (src/tools/painting/scriptbrush.md).
  Сайт axiomdocs.moulberry.com из облачного окружения недоступен.

НАСТРОЙКИ attach_brush.lua (окно Tool Options)
All leaves are targets, Custom target, Any solid block is a target,
Blocks to use, Block 1-6, Mode (1 кнопки/рычаги, 2 блоки с facing, 3 без
поворота), Density, Pattern seed, Place on top/below/on sides, Face the target,
Facing may be up or down.
Логика: на каждой цели проверяются 6 соседей; воздух с вероятностью Density
получает блок; поворот: кнопка на полу/потолке получает face=floor/ceiling и
случайный facing, на стене face=wall и facing от цели (или к цели с
"Face the target"). Случайность стабильна по позиции и сиду (math.sin).
